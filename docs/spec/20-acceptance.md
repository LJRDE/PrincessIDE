# PrincessIDE 验收标准 v1

> 状态：待用户确认。
> **铁律：一切"完成"必须由可执行命令的真实输出证明。** 不接受"读代码看起来对"、不接受"预期应该能跑"、不接受编造输出。
> 每份验收报告必须包含：**执行的命令原文 + 截取的真实输出 + 退出码**。

---

## 0. 通用规则

| 规则 | 说明 |
|---|---|
| 无头可测 | 所有验收必须能在无显示器的容器里跑通。GUI 视觉检查**不在**自动验收范围内，由用户本地确认 |
| 负样本必测 | 每个正向断言都要配一个失败路径断言（构建失败、启动超时、符号缺失） |
| 夹具固定 | 依据 `fixtures/refkernel/` 的参考内核；断言字符串与符号名固定，不得随实现漂移 |
| 报告落盘 | 报告写入 `docs/reports/<phase>.md`，命令与输出原样保留 |
| 独立复核 | 每个实现 Agent 的产出由**独立验收 Agent**（不同模型）按本文档复核 |

**固定断言常量**（改这些值等于改契约）

```
横幅字符串 : PrincessIDE reference kernel booted
故障符号   : refkernel_fault_probe
参考内核   : fixtures/refkernel/
```

## P1 选型 spike

每路 spike 的通过条件是**证据而非观点**：

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| P1-A | 编辑器与 clangd 路线 | 报告 + **实测**：clangd 对参考内核给出补全/跳转/诊断的真实截图或 JSON-RPC 交互记录 |
| P1-B | Tauri 进程编排 | 报告 + 最小可运行验证：Rust 侧起子进程并把 stdout 以事件流推给前端（在无 GUI 环境下用单测或 headless 方式证明） |
| P1-C | 调试协议路线 | 报告 + 实测：GDB 能否以 DAP 直接对接（`gdb -i=dap` 是否可用），或必须自写 MI 适配层；给出结论与反例 |
| P1-D | 二进制/底层工具链选型 | 报告 + 实测：对夹具 ELF 解析段节/符号/源码行的库选型，附真实输出 |

每份 spike 报告必须含：**结论 / 备选方案 / 放弃理由 / 在本环境可复现的命令**。

## P2 核心引擎（价值大头）

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| P2-1 | 单元测试 | `cargo test --workspace` 全绿 |
| P2-2 | 构建 E2E | 对参考内核执行构建 → `build.finished.status=ok`，`artifacts[]` 含 `kernel.elf` |
| P2-3 | 运行 E2E | QEMU 无头启动 → 串口事件流中出现横幅字符串 |
| P2-4 | fault E2E | `run.fault` 事件带 `rip`，且 `symbolicated = { symbol: refkernel_fault_probe, file, line }` |
| P2-5 | 退出归因 | `run.exited.reason` 正确区分 `guest-shutdown` / `triple-fault` / `timeout` / `killed` |
| P2-6 | **负样本**：构建失败 | 故意引入语法错误 → `status=failed` + `build.diagnostic` 带正确 `file`/`line` |
| P2-7 | **负样本**：启动超时 | 内核死循环 → 超时后进程组被杀干净（无孤儿 QEMU 残留），`reason=timeout` |
| P2-8 | 事件契约 | 录制的事件 JSON 通过 `princess-core` 反序列化校验，且 `seq` 单调 |

## P4 调试器

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| P4-1 | 无头断点 E2E | 脚本起 `qemu -s -S`，在 `kmain`（或参考内核固定符号）下断 → 断言停在预期位置，RIP 匹配 |
| P4-2 | 寄存器/内存 | 读取 `RIP`/`CR3` 与指定物理内存，值与 GDB 直接查询一致 |
| P4-3 | 单步与栈 | 单步后地址变化符合预期；`stackTrace` 能跨 C/汇编混合帧给出源码行 |
| P4-4 | 反向验证 | 给错误符号名时必须明确失败，不得返回看似合理的假数据 |

## P5 底层可视化

| 编号 | 验收项 | 通过条件 |
|---|---|---|
| P5-1 | ELF 解析 | 对夹具 ELF 的段节/符号/入口点与 `readelf`/`objdump` 输出一致（golden 文件比对） |
| P5-2 | 反汇编 | 指定函数反汇编与 `objdump -d` 一致（允许格式差异，指令语义必须一致） |

| P5-4 | QEMU monitor 解析 | 用**录制**的 `info mem` / `info registers` / `info tlb` 样本做固定夹具解析断言 |
| P5-5 | 页表/GDT-IDT | 能按 CR3 逐级走下页表并解析项；解析失败时明确报错 |
